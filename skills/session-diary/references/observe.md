# 관찰 기준

## AI를 쓰는 방식: 관찰할 행동 11개
**그날 가장 크게 맡긴 일이 있던 세션 하나**에서 행동별로 보였는지만 판단한다. 맡긴 범위가 넓고 내 발화가 3개 이상인 세션을 고른다. 다른 세션까지 합치면 바쁜 날은 11개가 전부 보여 비교할 것이 없고, 세션마다 세면 판정이 수백 번 들면서 재현되지 않았다. 보인 행동의 키를 일기 머리말 `seen`에 적고, 일기가 쌓이면 "최근 N일 중 M일"로 비교한다. 안 보인 행동을 지적으로 삼지 않는다. 일이 요구하지 않았을 수 있다. 행동 목록은 Anthropic AI Fluency Index의 관찰 가능한 행동을 옮겼다.

| 키 | 행동 | 이렇게 보이면 "보임" |
|---|---|---|
| `iterates` | 다듬기 | 첫 답을 그대로 받지 않고 후속 요청으로 결과를 고친다 |
| `goal` | 목표 먼저 말하기 | 무엇을 왜 하려는지 요청 안에 있다 |
| `examples` | 좋은 예 주기 | 원하는 수준의 예시나 참고 자료를 준다 |
| `format` | 형식 정하기 | 결과의 구조나 형식을 정한다 |
| `mode` | 진행 방식 정하기 | "먼저 질문해", "반박해 줘"처럼 AI가 일하는 방식을 정한다 |
| `tone` | 말투 정하기 | 글의 말투나 문체를 정한다 |
| `missing_context` | 빠진 맥락 짚기 | AI가 모르는 사실을 알아채고 알려 주거나 물어본다 |
| `audience` | 독자 정하기 | 결과를 볼 사람을 말한다 |
| `questions_reasoning` | 근거 따지기 | AI의 논리에 이의를 달거나 왜 그런지 묻는다 |
| `consults_first` | 먼저 상의하기 | 실행 전에 접근 방법을 묻는다 |
| `checks_facts` | 사실 확인 | 결과를 직접 돌려 보거나 자료와 대조한다 |

헷갈리면: 「왜 이렇게 했어?」, 「이게 맞아?」처럼 AI의 논리를 묻는 것은 `questions_reasoning`, 직접 돌려 본 결과나 자료를 내미는 것은 `checks_facts`, AI가 모르는 사실을 알려 주는 것은 `missing_context`다. 한 발화가 둘에 걸치면 둘 다 보인 것으로 친다.

읽을 때 주의할 것:
- **기록에 없는 행동이 많다.** 머릿속 검토, 다른 화면에서의 시험은 보이지 않는다. 책임 있는 사용(공유 전 검증, AI 사용 공개) 같은 행동은 대부분 대화 밖에서 일어나 여기서 재지 않는다.
- **만드는 일을 맡긴 세션을 특히 본다.** Anthropic 분석에서 코드나 문서를 만드는 대화는 지시는 많아지고 평가 행동(맥락 짚기, 사실 확인, 근거 따지기)은 줄었다. 결과가 완성돼 보이면 덜 따지게 될 수 있다.
- **그쪽의 비율을 기준으로 쓰지 않는다.** 그 수치는 Claude.ai 사용자 대상의 관찰값이고 코딩 도구나 이 사람의 기준이 아니다. 비교는 지난 일기의 나와만 한다. 추세는 일기 5개가 쌓인 뒤에 말한다.

## 일하는 방식: 볼 것
- 시작 때 목표와 "다 됐다"의 기준이 있었나, 도중에 바뀌었나
- 같은 내용을 다시 설명하거나 같은 요청을 반복한 곳
- 바로 앞 답변에 있던 내용을 다시 물은 곳 (읽지 않고 넘어간 신호). 재료는 짧은 질문 앞의 AI 답변을 800자까지 남긴다. 잘려서 확인되지 않으면 쓰지 않는다
- 결정을 내가 내렸나, AI가 낸 안을 그대로 받았나. 앞에 논의 없이 보낸 "고쳐줘", "구현해"는 맡긴 것으로 본다. 긴 논의 끝의 "좋아, 구현해줘"는 결정일 수 있으니 맡긴 것으로 치지 않는다
- 세션을 여러 개 동시에 열었을 때 끝맺지 못하고 남은 일
- 남겨 둘 만한 판단을 규칙, 문서, 스킬로 남겼나

## 피드백을 쓰는 법
- 지적은 작업과 행동에 붙인다. 사람의 성향이나 능력을 말하면 주의가 일에서 자기 자신으로 옮겨가 효과가 떨어진다.
- 지적마다 **무슨 일이었나 → 왜 비용이 됐나 → 다음엔 무엇을** 순서로, 쉬운 말로 한 덩어리로 쓴다. 원문은 번호로만 잇고 근거 칸에 둔다.
- 잘한 행동도 같은 기준으로 쓴다. 무엇을 왜 잘했는지 알아야 다시 할 수 있다.
- 비용이 실제로 드러난 장면(다시 한 작업, 뒤집힌 결정)을 우선한다.

| 하려던 것과 실제의 차이를 묻는 구조 | 미 육군의 사후 검토(After Action Review), What? So what? Now what? 성찰 틀 | 널리 쓰이는 틀이고, 이번에 원문을 확인하지는 않았다 |

이 프로젝트의 앞선 실험(`session-profile`, git 기록에 있음)에서 얻은 것:
- AI 판정자는 문제를 과하게 붙인다. 어긋남 판정을 다시 따지면 33개 중 12개, 9개 중 3개만 남았다. 그래서 지적을 다시 따지는 단계를 둔다.
- 숫자 점수는 본인이 약점으로 여긴 것을 가렸다(기준 점수 78~93). 그래서 점수를 매기지 않는다.
- "네"만으로는 이해했는지 알 수 없다. 짧은 승인 장면 14개 중 이해가 확인된 것은 0개였다.
