# session-playbook: 세션에서 노하우와 프롬프트 뽑기

지난 작업 세션을 읽어, 다음에 같은 종류의 일을 맡길 때 쓸 프롬프트와 스킬 후보로 만든다. 읽는 대상은 Claude Code 세션이다(Codex 기록은 아직 읽지 않는다).

아래 `<스킬>`은 이 스킬 폴더의 절대 경로다. 결과 파일은 `~/.session-playbook/`에 저장한다. 대화 원문이 섞이므로 공개 저장소에 올리지 않는다.

## 절차
1. **목록 보이기.**
   ```bash
   python3 <스킬>/scripts/sessions.py list
   ```
   출력을 그대로 보여 주고 분석할 번호를 묻는다(여러 개). 오래된 것이 필요하면 `--days 30 --limit 30`을 붙인다. 이 스크립트가 지금 대화, 프로그램이 띄운 실행, 임시 폴더 실행은 뺀다.

2. **고른 세션 읽기.**
   ```bash
   python3 <스킬>/scripts/sessions.py show 2 4 7
   ```
   세션마다 제목, 쓴 도구, 고친 파일, 줄인 대화가 나온다. 긴 세션은 가운데가 `...(N턴 생략)...`로 줄어 있다. 결론이 그 생략 구간에 있어 보이면 `--budget 30000`으로 다시 뽑는다.

3. **분석하고 쓰기.** `references/format.md`의 구조와 규칙대로 쓴다. 핵심은 세 가지다.
   - 작업 명세: 세션마다 무슨 일이었는지와 공통 작업 유형.
   - 노하우: 해 본 사람만 아는 판단과 요령. 조건이 붙은 판단을 그렇게 고른 기준과 함께 적는다. 사용자가 AI를 고쳐 준 말, 되돌린 결정, 반복한 요구에서 뽑고, 근거 인용이 없는 노하우는 쓰지 않는다. 노하우마다 스킬의 어느 칸(켜는 말, 절차, 규칙, 완료 점검, 사람에게 묻기)으로 갈지 적는다.
   - 스킬 후보: 절차가 있고, 지시가 명확하고, 반복된 작업만. 켜는 말, 다 됐다의 기준, 사람에게 남길 판단을 세션 근거로 채운다. 붙여 쓸 프롬프트.

4. **저장하고 알리기.** `~/.session-playbook/<오늘 날짜>-<주제>.md`에 저장한다. 같은 이름이 있으면 덮어쓰지 않고 `-2`를 붙인다. 파일 위치, 노하우 개수, 스킬 후보 이름을 짧게 알리고, 프롬프트 한 덩어리를 어디에 쓰면 되는지 한 줄로 말한다.

## 하지 않는 것
- 사용자가 고르지 않은 세션을 읽거나 분석하기.
- 근거 없는 일반론을 노하우로 쓰기. 세션에서 확인한 것과 추측을 구분한다.
- 결과를 스킬 파일, 기억 파일, 저장소로 옮기기. 사용자가 원하면 그때 한다.
- 대화에 있던 키와 비밀값을 파일에 옮기기. 스크립트가 정해진 패턴만 가리므로 쓰기 전에 한 번 더 본다.
